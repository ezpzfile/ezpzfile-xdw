# EZPZ File XDW: 계획과 진행 상황

[日本語](PLAN.ja.md) · [English](PLAN.en.md) · **한국어**

DocuWorks(.xdw) 문서를 어디서나(맥·리눅스·휴대폰·브라우저) 열고, 주석을 달고, 다시 .xdw로 저장하는 오픈소스.
JTD 때와 같은 방식: **엔진(Rust) + 한 파일짜리 웹 편집기 + 공개 규격서 + 진짜 뷰어로 검증**.

## 원칙

- 처음부터 새로 만든다. 다른 프로젝트(xdw-salvage 등)는 답 맞춰 보기용으로만 읽는다.
- 진짜 DocuWorks Viewer Light를 심판으로 쓴다. 규격서의 [viewer] 표시는 실제로 파일을 만들어 열어 본 것.
- 저장은 **파일 전체를 새로 써서 지금 쓰는 데이터만 남긴다**(2026-10-07부터). 지운 쪽이나 주석은 파일에 남지 않는다.
  서명이 있는 문서만 DocuWorks와 같이 끝에 한 묶음(세그먼트)을 덧붙여 서명한 때의 내용을 남긴다. 어느 쪽이든 모르는
  부분은 바이트 그대로 옮긴다.
- 파일에 적힌 크기와 개수는 믿지 않는다. 실제 데이터와 맞춰 보고 상한을 넘으면 멈춘다(v0.3).
- 저장한 파일은 다시 읽어 비교하고, 다르면 저장하지 않는다.
- ezpzfile.com 에는 영향 없음 (별도 저장소).

## v0.3 (2026-10-02 ~ 2026-11-04): 글자 선택·찾기, 비치는 그림, 새로 쓰는 저장, 믿을 수 없는 파일 대비

| 항목 | 상태 |
|---|---|
| 쪽 안 글자 선택·복사 | 완료. 그려진 글자 위에 보이지 않는 글자 층을 겹침. Ctrl+A는 그 쪽 글자 전체 선택 |
| 문서 안 찾기(Ctrl+F) | 완료. 전각·반각, 대문자·소문자 차이를 무시하고 찾아서, 찾은 글자를 골라 보여 줌 |
| 비치는 그림 | 완료. 흰 부분으로 밑의 글자가 보임. DocuWorks에는 비치는 그림 주석이 없어서, 클립보드에서 붙인 그림과 같은 모양(OLE 확장 메타파일)으로 저장하고 그 안에서 그림을 쪽과 곱해서 그림. DocuWorks 10에서도 똑같이 보이고 옮기기·크기 바꾸기도 됨 (명세 5.5) |
| 안 비치는 그림 | 전처럼 DocuWorks 그림 주석. 속성 창에서 비치게·안 비치게를 바꿀 수 있음. 투명한 부분이 있는 그림(PNG 등)은 비치는 그림으로 붙음 |
| 그림 크기 바꾸기 | 완료 (모서리 끌기) |
| 보호된 문서 알아보기 | 완료. 암호나 전자 인증서로 보호된 문서를 깨진 파일이 아니라 "보호된 문서"로 알아보고, DocuWorks에서 보안을 푼 뒤 열라고 안내. 이 편집기는 암호를 다루지 않음 |
| 서명 정보 표시 | 완료. 서명을 고르면 종류(전자 도장인지 인증서인지)·서명 모듈(`%smin`)·버전(`%sigver`)이 나옴. 지금도 유효한지 확인은 DocuWorks나 인증서 검증이 필요(아직) |
| 파일 전체를 새로 쓰는 저장 (10/07) | 완료. 지금 쓰는 엔트리만 번호를 새로 매겨 세그먼트 하나짜리 파일로 씀. 지운 쪽이나 주석이 남지 않음. 서명이 있는 문서만 끝에 덧붙임. 공개 견본 39개를 새로 쓰고 편집해 저장한 파일을 Viewer Light에서 확인 |
| 새 문서 (10/07) | 완료. 빈 A4 한 쪽, DocuWorks 10이 만드는 문서와 같은 모양. 아무것도 열지 않은 채 PDF나 그림을 끌어다 놓으면 그것으로 새 문서를 만듦 |
| PDF에서 가져온 쪽의 글자 (10/28) | 완료. 엔진(core)의 `Document::insert_image_page_text`가 쪽 그림 안에 글자를 먼저 그리고 그 위에 쪽 그림을 놓음. 모양은 같고, 찾기·선택·복사·PDF 글자 층에 글자가 남음(DocuWorks에서도). PDF에서 글자와 위치를 꺼내는 일은 웹 편집기(pdf.js)가 하고 wasm `insertImagePageText`로 넘김 |
| 믿을 수 없는 파일의 상한 (11/04) | 완료. 파일에 적힌 푼 크기를 미리 잡지 않고 상한(`maxExpand`, `maxRatio`)과 맞춰 본 뒤 실제로 푼 만큼만 씀. 그림 화소 수, 한 쪽의 그리기 기록 수와 점 수, 쪽 수, 작업 메모리에도 상한(`Limits`, `Document::open_with`). 기록 안의 개수는 기록에 들어 있는 만큼으로 자름. 넘으면 `TooLarge`("too large or damaged"). 브라우저 엔진은 최대 1 GiB, 편집기는 Web Worker에서 확인한 뒤 엶(`web/worker/ezpzxdw-safe.js`) |
| 가린 글자 빼기 (11/04) | 완료. 나중에 그려진 불투명한 칠이나 그림에 완전히 가린 글자는 텍스트·PDF 글자 층·편집기 글자 선택에서 뺌(기본). 형광펜, 반투명한 그림, 같은 그림 안의 그림(스캔, PDF에서 가져온 쪽)은 가리개로 보지 않음. `include_hidden` / `setIncludeHidden(true)` / `--include-hidden`으로 남길 수 있음. 뺀 수는 `hidden_chars` |

## 검증 방법

- `cargo test` + `EZPZXDW_CORPUS=…`: 코퍼스 전체 읽기, 모든 쪽 그리기, 편집·저장·다시 읽기.
- `tools/dwview`: 저장한 파일을 진짜 Viewer Light로 열기.
- `tools/dwapi`: DocuWorks 10 자체(API)로 저장한 파일을 열고 그려서, 쪽·주석 수가 우리 엔진과 같은지 비교.
- `tools/webshot`: 편집기를 사람처럼 조작해서 저장까지, 뷰어 화면과 나란히 비교.
