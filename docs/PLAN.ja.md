# EZPZ File XDW: 計画と進捗

**日本語** · [English](PLAN.en.md) · [한국어](PLAN.ko.md)

DocuWorks（.xdw）文書を、どこでも（Mac・Linux・スマホ・ブラウザ）開いて、アノテーションを付けて、
もう一度 .xdw として保存するためのオープンソース。
JTD と同じ進め方: **Rust のエンジン + 1 ファイルの Web エディタ + 公開の形式仕様書 + 本物のビューアでの検証**。

## 原則

- ゼロから作る。ほかのプロジェクト（xdw-salvage など）は答え合わせのためにだけ読む。
- 本物の DocuWorks Viewer Light を審判にする。仕様書の [viewer] 印は、実際にファイルを作って開いて確かめたもの。
- 保存は DocuWorks と同じ方式: 元のデータはそのままにして、**末尾に 1 つのまとまり（セグメント）を追加する**。
  わからない部分には手を付けない。
- 保存したファイルは読み直して比較し、違っていれば保存しない。
- ezpzfile.com には影響しない（別のリポジトリ）。

## 次にやること

1. **パスワード**: DocuWorks API でパスワード付きのサンプルを作って方式を調べ、パスワードを知っている人が開けるようにする（本文レコードが暗号化されている）。
2. **署名の検証**: 証明書を調べて、署名がいまも有効かを示す。新しく署名を付けるのはその後。
3. **添付された原本ファイル（1306）** の取り出し。
4. 新しいバインダーの作成（今は既存のバインダーの編集のみ）。
5. マーカー・多角形など残りのアノテーションの種類（DocuWorks API でサンプルを作って照合できる）。

## 検証の方法

- `cargo test` + `EZPZXDW_CORPUS=…`: コーパス全体の読み込み、全ページの描画、編集・保存・読み直し。
- `tools/dwview`: 保存したファイルを本物の Viewer Light で開く。
- `tools/dwapi`: DocuWorks 10 そのもの（API）で保存したファイルを開いて描き、ページ数とアノテーション数を
  このエンジンと比べる。
- `tools/webshot`: 人と同じようにエディタを操作して保存まで行い、ビューアの画面と並べて比べる。
