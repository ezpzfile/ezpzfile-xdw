# XDW 실험 결과 (2026-10-01)

심판: **DocuWorks Viewer Light 10** (FUJIFILM 무료 뷰어). 클라우드의 Wine(일본어 환경)에서 자동 실행 — `tools/dwview`.
코퍼스: 공개 파일 43개 (`corpus/manifest.tsv`, 세대 7·10, .xdw·.xbd).

## 1. 검사값(체크섬) — 가장 중요한 발견

원본에서 1바이트씩 바꿔 뷰어로 열어 봄:

| 바꾼 곳 | 결과 | 뜻 |
|---|---|---|
| 마지막 트레일러의 0x85 | **거부** ("The file is not a DocuWorks document file.") | 이 값은 검사됨 |
| 항목(쪽)의 0x81 | 열림 | 항목 검사값은 열 때 검사 안 함 |
| 쪽 그림 데이터 | 열림 (그림만 깨짐) | 데이터 자체는 검사 안 함 |
| 속성 블록 | 거부 | 속성 블록이 0x85로 검사됨 |
| 이전 세그먼트의 트레일러·속성 | 열림 | 마지막 트레일러만 쓰임 |
| 트레일러 0x86(자기 길이) | 거부 | 파일 끝에서 트레일러를 찾는 데 씀 |
| 머리(0x60) | 거부 | |

계산법: 블록의 4바이트(리틀 엔디언) 단어를 모두 XOR. 코퍼스의 트레일러 26/26, 항목 463/463 일치.
속성을 우리 압축기로 다시 압축(크기·바이트가 원본과 다름) + 검사값 다시 계산 → **열림**.

## 2. DocuWorks 전용 그리기 기록 (DW…)

시험 그림을 넣은 쪽을 만들어 뷰어로 확인 (`tools/dwview`):

- `DW02` 경로 시작 / `DW03` 잘라내기 / `DW04` 채우기 / `DW05` 선 / `DW06` 사각 잘라내기
- 점 기록: 첫 점 i16, 이어서 i16·i8·니블(4비트) 걸음. 니블 8은 "다음 바이트에 걸음" (코퍼스 25,790개 기록에서 길이 정확히 맞음)
- op 비트: 0x01 새 도형, 0x02 닫기, 0x10 베지어, 0x20 단독 다각형(채우기), 0x40 단독 꺾은선
- 사진: `DWa` 기록 안 그림, `DWb` 쪽의 사진 목록에서 다음 것, `DWc` 그리기
- 옛 WMF 쪽의 `DW 02 00/01/02/03` (그림, 다음 사진, 그리기, 띠 채우기)

## 3. 저장한 파일 열기

| 묶음 | 파일 | 결과 |
|---|---|---|
| 손으로 만든 변형 (속성 다시 압축, 쪽 그림 교체, 회전 61, 주석 다시 그림) | 20여 개 | 모두 예상대로 |
| 코퍼스 38개(6 MB 이하)에 편집 적용: 텍스트·형광펜·사각형·타원·직선 주석 추가 + 1쪽 회전 | 38 | **38/38 열림**, 주석·회전 모두 보임 |
| 웹 편집기에서 사람처럼 조작(Playwright) → 저장한 .xdw | 1 | 열림, 주석 5종·이동·2쪽 회전 그대로 |
| 같은 세션의 PDF | 1 | 화면과 같음, 글자 검색·복사 됨 |

알게 된 것: 뷰어는 주석을 **저장된 그림으로** 그린다 (설정만 바꾸면 화면은 그대로, 그림을 지우면 주석이 사라짐) → 주석을 추가·변경할 때 그림을 함께 만들어 넣음.
`61 = 90` 은 시계 방향 회전. 형광펜은 `R2_MASKPEN`(곱하기)로 그리면 밑글씨가 보임.

## 4. 화면 비교

코퍼스 43개 1쪽을 뷰어 화면과 우리 편집기 화면으로 나란히 비교 (`tools/webshot/compare.sh`).
글자·표·사진·지도·회전된 쪽·주석 모두 같은 모양. 차이는 글꼴(뷰어는 MS 글꼴, 우리는 기기 글꼴)과 부드러움 정도.

자동 테스트: `EZPZXDW_CORPUS=… cargo test` — 43개 전부 읽기, 모든 쪽 빠진 기록 없이 그리기, 속성 바이트 단위 왕복, 편집 후 저장·다시 읽기.

DocuWorks Desk(정식판)는 체험판 다운로드에 FUJIFILM 계정 가입이 필요해서 아직 확인하지 못했다.

## 6. DocuWorks 10 정식판으로 확인 (2026-10-01)

사용자가 받아 준 **DocuWorks 10.1.1 체험판**(로그인 없이 60일)을 클라우드 Wine에 설치.
DocuWorks Desk와 함께 설치되는 **DocuWorks API(xdwapi.dll)** 가 Wine에서 동작 → DocuWorks 엔진이 직접 파일을 읽고 그리게 함 (`tools/dwapi`).

| 시험 | 결과 |
|---|---|
| DocuWorks API로 日付印·付箋·글상자를 만들게 해서 저장 → 우리 도구로 속성 읽기 | 진짜 이름 확인: 日付印 `STAMPATT_POST/NAME/YEAR…`, 付箋 `FSN_COLOR` + 안에 글상자(자식). 우리가 추측한 이름(`%TopField` 등)은 API용 이름이었음 → 진짜 이름으로 고침 |
| 고친 뒤 우리가 만든 日付印·付箋을 DocuWorks API로 읽기 | 위 글자·아래 글자·날짜·색, 付箋 색·안의 글자까지 DocuWorks가 만든 것과 똑같이 읽힘 |
| 코퍼스 38개에 모든 편집(日付印·付箋·글상자·형광펜·사각형·타원·직선·그림·빈 쪽·사진 쪽·쪽 복사·회전, .xbd는 + 문서 추가·이름·순서) | **38/38**: 쪽 수·쪽별 주석 수가 우리 읽기와 일치, 첫 쪽·마지막 쪽 그리기 성공 |
| DocuWorks 10 샘플 5개(스캔·사진·설계도·계약서·바인더)에 같은 편집 | **5/5** 일치·그리기 성공 |
| 웹 편집기로 저장한 .xdw·.xbd | 2/2 일치, 日付印·付箋 속성 정확 |
| DocuWorks Desk 화면 | 우리 파일 4개가 목록에 쪽 수·썸네일(도장·付箋 보임)과 함께 표시. DocuWorks 10의 Viewer Light(빠른 보기)로 열림 |
| DocuWorks Viewer(편집용) | Wine에서 실행 중 오류로 꺼짐 (DocuWorks 파일과 무관, Wine 호환 문제로 보임) |

새로 알게 된 것:
- DocuWorks 10 스캔·사진 쪽은 그림 종류 **5 (JPEG 그대로)** → 우리 화면에 안 나오던 것을 고침
- DocuWorks 10 바인더는 문서 이름을 **70 (UTF-16)** 에 씀 → 읽기·이름 바꾸기 모두 지원
- 종류 0x8043 = **서명(電子印鑑)**. 편집하면 서명이 무효가 되므로 편집기에서 열 때 알려 주고, 서명은 옮기거나 지울 수 없게 함
